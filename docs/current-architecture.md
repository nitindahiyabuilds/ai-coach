# AI OS — Current Engineering Checkpoint

## What exists today

AI OS currently has a history-aware AI health/fitness coach.

The current workout intelligence pipeline is:

Raw workout data
→ Workout analysis
→ 3-session trend + training recency
→ Deterministic progression decision
→ Deterministic workout plan
→ LLM-generated reasoning
→ Coach API
→ Workout Plan UI

## Workout data

Workout history is stored in Supabase using:

- `workout_sessions`
- `workout_sets`

Row Level Security is enabled and users can only access their own workout data.

## Workout analysis

`lib/analysis/workout.ts`

The analysis layer derives:

- latest workout session
- previous workout session
- latest exercise performance
- previous exercise performance
- three-session trend
- total volume
- top set
- top-weight change
- top-rep change
- volume change
- days since the exercise was last trained

These values are computed deterministically from stored workout data.

## Progression

`lib/analysis/progression.ts`

The progression layer determines the recommended:

- weight
- sets
- reps
- progression decision
- reason code
- training recency

The LLM does not determine workout numbers.

## Workout plan

`lib/analysis/workout-plan.ts`

The deterministic progression output is converted into a structured workout plan.

The plan contains:

- exercise name
- sets
- reps
- weight
- decision
- reason code
- days since last trained

## AI reasoning

`lib/ai/coach/workout-plan-prompt.ts`

The LLM receives the deterministic plan and explains the recommendation.

The LLM is explicitly instructed not to change:

- exercise
- weight
- reps
- sets
- progression decision

Therefore:

Deterministic code decides WHAT the user should do.

LLM decides HOW to explain it.

## Coach API

`app/api/coach/route.ts`

The Coach API currently:

1. validates the user's question
2. builds user context
3. loads workout analysis
4. loads conversation history
5. generates the normal coach response
6. generates a deterministic workout plan when workout data exists
7. generates LLM reasoning for the plan
8. combines the deterministic plan with the reasoning
9. returns the response to the frontend
10. saves the conversation

## Current UI

The Coach UI currently supports:

- conversational messages
- structured workout plan rendering
- exercise name
- recommended weight
- sets and reps
- progression decision
- days since last training
- AI reasoning

The main components are:

- `components/coach/CoachChat.tsx`
- `components/coach/WorkoutPlanCard.tsx`

## Not finished

The following are intentionally incomplete:

- per-set workout logging UI
- immediate persistence of logged sets
- session completion
- next-recommendation loop
- complete end-to-end plan → workout → logging → next plan flow
- further UI polish
- performance optimization of the Coach request

These should not be considered completed features.

## Architectural principle

The key design principle of the current implementation is:

> Use deterministic application code for decisions that can be calculated from structured data. Use the LLM for explanation, reasoning, and conversational framing.

The workout recommendation numbers are therefore not generated by the LLM.
